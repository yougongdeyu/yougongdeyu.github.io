skb结构和流动
skb就是一层层协议头+payload，每层方法就是一个处理该层管理的网络头数据，发送添加，接受去掉。最后被放入socket的receive buffer或者离开send buffer

NAPI:

协议栈：
TCP 哈希表就是一堆建立好了的tcp_sock，一层层解析到 tcp就是找到五元组对应的socket。然后放入receive buffer。

tcp是面向流的，不会丢失和乱序:
应用层比如http 保证消息边界，比如一个tcp里面包含了多个请求，tomcat http层解析为请求，然后不同线程处理，最后返回的时候保证一个个response不会错乱地放入tcp流里面。如果是http2.0，可以同时写入，但都是应用层保证。

chrome的复用:
如果是server端一样，它是可以复用的，这样不用建立新的连接。浏览器维护一个 连接池 Map：发请求时：查找对应 key，找空闲连接 → 复用，没有 → 建立新连接请求完成后：
HTTP/1.1 keep-alive → 连接回到空闲池
HTTP/1.0 或非 keep-alive → 关闭连接




一个 socket fd → 对应一条 TCP 连接
一个 TCP 连接 → 可以被浏览器复用来承载 多个应用层请求
TCP 只传字节流，应用层协议保证请求/响应不混淆

同一个 socket 文件可以承载多个请求，关键是 应用层协议解析边界
HTTP/1.1：请求1完成才能发送请求2 → TCP socket 上顺序写入
HTTP/2：请求1、请求2可同时写入 → TCP socket 上按 frame 分配 → 服务器根据 stream ID 拆分
