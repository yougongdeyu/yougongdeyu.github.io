一、事务与隔离级别

1. COMMIT 是不是事务结束？

答： 是。COMMIT 表示事务正式结束，所有更改对其他事务可见，并持久写入磁盘。

2. 一次事务可以多次执行 SQL 吗？

答： 可以。在 START TRANSACTION 与 COMMIT 之间，你可以执行多条 SQL，它们都属于同一个事务。COMMIT 后事务结束，再执行 SQL 会默认进入新事务（如果 autocommit=ON）。

3. REPEATABLE READ 是不是使用锁来实现的？

答： InnoDB 默认不是靠锁，而是靠 MVCC 的快照机制实现可重复读，防止不可重复读。用锁也可以实现，但性能差。

4. REPEATABLE READ 是否能解决幻读？

答： 可以（前提是使用 InnoDB 并且查询字段有索引）。InnoDB 使用 Gap Lock（间隙锁）来阻止插入数据，防止幻读。

二、MVCC 与快照机制

1. REPEATABLE READ 和 READ COMMITTED 区别？

答：

READ COMMITTED: 每次查询生成新快照，能看到已提交的新数据，可能发生不可重复读。

REPEATABLE READ: 第一次查询时生成快照，整个事务内都使用同一个版本，防止不可重复读。

2. 什么是快照？

答： 是事务开始时数据库的一个逻辑视图，基于 undo log 生成，仅自己可见。

三、锁机制与加锁行为

1. 锁的类型有哪些？

S 锁（共享锁）：允许并发读，阻止写

X 锁（排它锁）：自己能读写，别人不能读写

Gap 锁：锁住索引间隙，防止幻读（插入）

2. 加锁是行级锁还是页级锁？

答： InnoDB 使用的是行级锁，但锁信息以“页”为单位管理（页 ID 映射到链表）。

3. 锁信息存储在哪里？

答： InnoDB 有一张锁哈希表，key 是页 ID，value 是链表，记录每一行的锁。

4. 多条数据加锁时，如果其中一条被阻塞，前面的锁还有效吗？

答： 是。已经加的锁不释放，等其他锁都获得后继续执行；加锁是原子过程。

5. 锁哈希表是全局的吗？多个表之间会互相影响吗？

答： 是全局的，但如果锁住的是不同页（Page），不会互相影响。

四、页与数据存储结构

1. 数据是按什么单位存储的？

答： 数据存储在页（Page）中，一个页可以包含多行数据。聚簇索引的叶子页是表数据存储的实际位置。

2. 没有索引时如何查数据？

答： 使用全表扫描，页页读，行行比，性能较差。

3. %like% 没有索引时怎么查？

答： 会触发全表扫描，不加锁就无法阻止幻读。

六、Undo Log、MVCC 与当前读

1. Undo log 是什么？

答： 一种记录旧值的数据结构，用于回滚和生成快照版本。

2. 当前读与快照读的区别？

答：

当前读（加锁）：如 SELECT ... FOR UPDATE，会加锁并读最新值

快照读：不加锁，读快照值（MVCC）

3. 锁与快照读如何配合？

答： MVCC 用快照避免加锁，但遇到写/当前读还是要加锁（保证一致性）
